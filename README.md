# FLYMAR

Имиджевая главная FLYMAR на Next.js App Router, TypeScript, Tailwind CSS 4 и Framer Motion. Английская версия — `/`, русская — `/ru`.

## Запуск

Требуется Node.js 22+.

```sh
npm ci
npm run dev
```

Локальный адрес: http://127.0.0.1:3000.

```sh
npm run typecheck
npm run build
npm start
```

Сборка `standalone` подходит для собственного Node.js-хостинга. Можно также подключить GitHub-репозиторий к хостингу с поддержкой Next.js. `npm start` по умолчанию слушает только loopback; для контейнера используйте `next start --hostname 0.0.0.0` или standalone `server.js` с переменными `HOSTNAME` и `PORT`. GitHub Pages без серверной части не поддерживает обработчик заявок.

## Что готово

- Адаптивная главная, оригинальный логотип и оптимизированные WebP из материалов клиента.
- Переключаемый первый экран, анимация появления секций, мобильная навигация.
- Три разных сообщения hero; второй блок Autonomy First с крупными 30 узлами и 70 км по эскизу.
- Слайдер F8 / F11 с кнопками, переключателями моделей, свайпом и клавиатурой.
- Отдельные страницы `/models/f8`, `/models/f11` и их русские версии `/ru/models/f8`, `/ru/models/f11`, характеристики и галереи.
- Раздельное позиционирование: F8 — универсальное электрическое судно для отдыха, поездок и работы; F11 — транспортная платформа для городов и операторов флота. У F8 — фотосценарии и владение, у F11 — инженерная подача, схема сети, эксплуатация и факторы стоимости владения.
- F11 представлен как Coming Soon: на странице модели и в её карточке нет опубликованных технических характеристик; визуализации обозначены как предварительная концепция.
- Нативные модальные окна: F8, интерьер, технологии, форма заявки. Escape, управление клавиатурой, возврат фокуса.
- Уважение системной настройки reduced motion.
- RU/EN, метаданные, изображение для социальных сетей, иконка.
- Страницы About, Contacts и Technology (`/about`, `/contacts`, `/technology` и версии с `/ru`), ссылки в шапке и подвале, форма заявки со страницы контактов.
- Серверная проверка полей заявки и готовый адаптер доставки.
- События аналитики без содержимого формы и персональных идентификаторов.

## Админка и хранение

Вход: `/admin` (перенаправляет на `/admin/login`). Три раздела: аналитика за 7 / 30 / 90 дней, заявки с поиском и UTM, настройки Telegram с несколькими получателями.

Для новой локальной установки скопируйте `.env.example` в `.env.local` и выполните `npm run admin:setup`. Скрипт запрашивает логин и скрытый пароль, сохраняет scrypt-хеш и генерирует ключ шифрования. Пароль и ключи не включены в репозиторий. Локальные данные доступа этой рабочей копии уже настроены отдельно.

Без `DATABASE_URL` в режиме разработки используется память процесса: данные сбрасываются при перезапуске. Это явно показано в интерфейсе. Метрики не заполнены вымышленными значениями; тестовые заявки помечены. Лимиты локального хранилища: 20 000 событий и 2 000 заявок. В production временное хранение запрещено: без базы API возвращает ошибку, а не подтверждает потерянные заявки.

Для постоянного хранения подготовлены адаптер PostgreSQL `src/lib/admin/postgres.ts` и схема `db/001-admin.sql`. При запуске:

1. Указать `DATABASE_URL` с TLS-параметрами провайдера и выполнить `npm run db:init` для создания таблиц.
2. Перенести `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `ADMIN_ENCRYPTION_KEY` в секреты хостинга. Сохранить резервную копию ключа шифрования: без него уже сохранённый токен бота не расшифровать.
3. Указать точный HTTPS-адрес в `NEXT_PUBLIC_SITE_URL`, перезапустить сервер. Этот адрес используется и для проверки Origin.
4. Если reverse proxy гарантированно заменяет заголовок IP, указать его имя в `TRUSTED_CLIENT_IP_HEADER`. Иначе посетители делят общий лимит; произвольному X-Forwarded-For сервер не доверяет.

Структура хранилища вынесена в `AdminRepository`: посещения, заявки, настройки, сессии и атомарные ограничения частоты запросов. Подключение к живой PostgreSQL пока не проверено — база ещё не предоставлена. Миграция создаёт только таблицы проекта и индексы, её можно запускать повторно.

Защита: scrypt, сравнение без зависимости от совпавших символов, непрозрачная серверная сессия на 8 часов, HttpOnly / SameSite=Strict cookie (Secure в production), проверка доступа на каждом административном API, проверка Origin для изменений, no-store, запрет встраивания админки во frame. Смена хеша пароля отзывает существующие сессии. Лимит входа: 5 попыток на источник за 15 минут и 10 на аккаунт за 15 минут; считаются все попытки, включая успешные. В PostgreSQL ограничение атомарно и работает между несколькими экземплярами сервера. Для эксплуатации периодически удалять просроченные строки `flymar_rates` / `flymar_sessions`; срок хранения событий и заявок согласовать отдельно.

## Заявки и Telegram

`POST /api/enquiry` проверяет имя, email, длину полей, согласие, язык, honeypot и Origin; ограничивает частоту. Заявка сначала сохраняется, затем отправляется в подключённые каналы. Один requestId не создаёт повторную заявку при повторной отправке. Контакты доступны только в админке, в аналитические события не попадают.

Telegram настраивается в админке: токен BotFather и до 10 получателей (имя для удобства + числовой Chat ID). Для личных уведомлений каждый получатель сначала пишет боту /start; один @username недостаточен. Для группы бот должен состоять в ней. Токен хранится зашифрованным AES-256-GCM, в обычном ответе API отсутствует; кнопка «Показать» запрашивает его отдельно и скрывает через 30 секунд. Можно заменить или удалить токен. Для реальных отправок нужны и `TELEGRAM_DELIVERY_ENABLED=true` на сервере, и переключатель в админке. По умолчанию отправка выключена.

Опциональный `LEADS_ENDPOINT` получает JSON с полями name, email, company, message, locale, consent, source, submittedAt. `LEADS_API_TOKEN` передаётся только сервером как Bearer. Ошибка Telegram или внешнего обработчика не удаляет сохранённую заявку: статус доставки виден в админке. Автоматических повторов и очереди доставки пока нет; это можно добавить после выбора хостинга. Внешние каналы в ходе локальной проверки не вызывались.

## Аналитика

`src/lib/analytics.ts` отправляет события во внутренний `/api/analytics`. Опциональный `NEXT_PUBLIC_ANALYTICS_ENDPOINT` получает дополнительную копию; окончательный формат можно согласовать с внешней системой. Для отладки есть браузерное событие `flymar:analytics`.

События: page_view, section_view, cta_click, modal_open, hero_change, form_start, form_submit, form_success, form_error. Payload: id, event, properties, path, timestamp, sessionId, attribution. UTM: source, medium, campaign, term, content; сохраняется первая метка сессии и путь входа. Остальные query-параметры, содержимое формы и IP не записываются в события. sessionId хранится в sessionStorage и обновляется после 30 минут бездействия; это сессии вкладок, не уникальные люди. При Do Not Track сбор отключается. Админка не учитывается как посещение сайта.

Конверсия — доля сессий с сохранённой сервером заявкой среди сессий с просмотром страницы в выбранном периоде. Повторные заявки одной сессии не повышают конверсию. Заявки без sessionId (например, при DNT) отображаются в заявках, но не добавляются к числителю конверсии. Дневные отчёты используют UTC. События клиентские: показатели не являются защитой от накрутки ботами. Инструкции по формату внешнего endpoint можно добавить отдельно.

## Проверки

`npm test` проверяет расчёт конверсии и UTM, границы дат, ограничения входа, срок сессий, хеширование пароля, шифрование токена, Origin и отключение/частичную доставку Telegram с подменённым транспортом. `npm run typecheck` проверяет типы. Для сборки: `npm run build`.

## Передача и публикация
