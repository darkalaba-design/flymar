# FLYMAR UI Kit

Открыть `/ui-kit`. Ссылка также есть в админке. Маркетолог работает в браузере: выбирает пресет или меняет отдельные параметры, проверяет сайт, затем сохраняет оформление.

## Рабочий процесс

1. Войти в `/admin/login` и открыть **UI Kit · оформление**.
2. Настроить цвета, шрифты, масштаб текста/заголовков, межбуквенный интервал, высоту строки, плотность, скругления, высоту кнопок, линии, тени и движение.
3. Изменения сначала являются личным черновиком. «Предпросмотр на сайте» применяет его в текущей вкладке; «Открыть сайт» позволяет проверить реальные страницы EN/RU. Баннер возвращает в UI Kit и позволяет закончить предпросмотр. Черновик хранится в sessionStorage этой вкладки. Другие посетители его не видят.
4. «Назад» возвращает прошлый шаг. «Отменить изменения» возвращает сохранённую тему. Пресет FLYMAR Original возвращает исходный дизайн, но его тоже нужно сохранить для публикации.
5. «Сохранить для всего сайта» публикует тему. Уже открытые страницы обновляются при фокусе/возврате во вкладку либо в течение 30 секунд. Новые страницы получают тему с сервера до первого отображения.

Пресеты не публикуются автоматически. Отключение предпросмотра возвращает реальный сайт к сохранённой теме; образцы в UI Kit продолжают показывать выбранные значения. Тема поддерживает экспорт/импорт JSON версии 1, а CSS-кнопка копирует базовые переменные. Неизвестные ключи, CSS-код, URL шрифтов и значения вне допустимых диапазонов не принимаются.

## Хранение и размещение

- **Локальная разработка без базы:** `theme/site-theme.json`. Файл хранится в Git, переживает перезапуск и попадает на хостинг вместе с проектом. Замена файла атомарная, записи сериализованы.
- **Production с PostgreSQL:** запись `site-theme` в существующей таблице `flymar_settings`. Применяется схема `db/001-admin.sql` (`npm run db:init`); отдельная миграция не нужна. `DATABASE_URL`, административные переменные и `NEXT_PUBLIC_SITE_URL` должны быть настроены на хостинге. Для текущего адреса Vercel последний параметр — `https://flymar.vercel.app`.
- **Production без базы:** используется версия из файла проекта. Предпросмотр и экспорт работают, сохранение для всех отключено; serverless-диск не используется как постоянное хранилище.
- Если база временно недоступна, публичный сайт использует тему из файла, а редактор блокирует сохранение. Сохраняйте актуальную резервную копию темы в проекте.

Изменения защищены существующей административной сессией и проверкой Origin. Ревизия темы предотвращает потерю изменений: устаревшая вкладка получает конфликт, а не перезаписывает новую версию. Запись PostgreSQL использует транзакцию и advisory lock. Подключение к живой PostgreSQL не проверялось: база ещё не предоставлена.

Root layout рендерится по запросу через `connection()`: так сохранённая тема доступна всему сайту без пересборки и без вспышки старых цветов. Это осознанный переход публичных страниц на серверный рендеринг; развёртывание требует Next.js server/runtime, а не static export.

## Где менять систему

| Файл | Назначение |
| --- | --- |
| `src/lib/design/theme.ts` | Именованные основы, допустимые диапазоны, пресеты, проверка входных данных и преобразование в CSS |
| `theme/site-theme.json` | Текущая сохранённая локальная тема / production fallback |
| `src/app/foundations.css` | CSS-основы и производные переменные палитры, адаптивных размеров, отступов, интервалов, длительностей |
| `src/lib/design/catalog.json` | Подписи производных переменных в каталоге |
| `src/app/design-system.css` | Общие контракты кнопок, карточек, окон и изображений |
| `src/components/theme-provider.tsx` | Применение темы, личный предпросмотр, обновление открытых страниц |
| `src/lib/design/store.ts` | Хранение в локальном файле / PostgreSQL |
| `src/components/ui-kit/` | Редактор, каталог и живые образцы |

Все публичные стили (`globals`, `fleet`, `positioning`, `company`, `business-benefits`) используют общую палитру, шкалы текста и отступов. Производные цвета сохраняют исходные оттенки через relative RGB и изменяются вместе с базовым цветом. SVG-иконки A1–B3 используются как маски и получают `currentColor`; растровые фотографии и фирменный белый логотип не перекрашиваются.

Адаптивные размеры сгруппированы под `--fm-font-*`; коэффициенты `--fm-body-scale` и `--fm-heading-scale` меняют весь набор. `--fm-space-*` зависит от `--fm-density`. Семантические значения (`--ink`, `--paper`, `--muted`, `--line`) остаются совместимыми псевдонимами. Общие кнопки и поля в UI Kit используют те же CSS-классы, что и сайт. Компонент иконок общий с реальными блоками.

Добавляя новый блок, используйте существующие переменные. Новый производный размер/оттенок добавляйте в `foundations.css` и каталог; новые управляемые параметры — в `theme.ts`, CSS defaults и файл темы. Интерфейс редактора и административные экраны сохраняют стабильное оформление, чтобы неудачный эксперимент не мешал вернуть тему. Системное `prefers-reduced-motion` имеет приоритет над настройками анимации.

## Проверки

`npm run typecheck`, `npm test`, `npm run build`.

Тесты проверяют схемы/импорт, запрет CSS-инъекций, диапазоны, отсутствие неразрешённых CSS-переменных, локальное сохранение, конфликт параллельных записей и запрет записи на production-диск без базы. В браузере проверены переходы главная → About с черновиком, сохранение → новая вкладка RU/F8, восстановление Original, мобильная ширина 390px и модальное окно каталога. Изменения темы во время проверки возвращены к исходным.
